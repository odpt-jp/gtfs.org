# 運行情報(alert) {: #service-alerts}


運行情報(alert)を使用すると、ネットワーク上で障害が発生した際に更新情報を提供できます。個別の便(trip)の遅延および運休は、通常、[便の更新(trip update)](../trip-updates)を使用して伝達するべきです。

以下を提供することができます。

*   URL - 運行情報(alert)について詳しく説明するサイトへのリンク
*   Header text - 運行情報(alert)の要約
*   Description - 運行情報(alert)の完全な説明。これは常にヘッダーとともに表示されるため、この情報を繰り返すべきではありません。

## TimeRange {: #timerange}


運行情報(alert)は、指定された時間範囲内で適切な場所に表示されます。この範囲は、乗客にとって運行情報(alert)を確認することが有用である期間全体をカバーするべきです。

時間が指定されていない場合、運行情報(alert)はフィード内に存在する限り表示されます。複数の範囲が指定されている場合、それらすべての期間中に表示されます。

## EntitySelector {: #entityselector}


Entity selector を使用すると、この運行情報(alert)がネットワークのどの部分に影響するかを正確に指定できるため、ユーザーに最も適切な運行情報(alert)のみを表示できます。複数のエンティティに影響する運行情報(alert)には、複数の entity selector を含めることができます。

エンティティは GTFS 識別子を使用して選択され、以下のいずれかを選択できます。

*   事業者 - ネットワーク全体に影響します
*   ルート・路線系統(route) - ルート・路線系統(route)全体に影響します
*   ルート・路線系統(route)の種別 - この種別のすべてのルート・路線系統(route)に影響します。例: すべての地下鉄。
*   便(trip) - 特定の便(trip)に影響します
*   停留所等(stop) - 特定の停留所等(stop)に影響します

1つの `informed_entity` に、上記のフィールドを複数含めることができます。1つの `informed_entity` に複数のフィールドが含まれる場合、それらは論理 `AND` 演算子で結合されているものとして解釈するべきです。言い換えると、運行情報(alert)は、`informed_entity` で指定されたすべてのフィールドを満たすコンテキストにのみ適用するべきです。たとえば、1つの `informed_entity` に `route_id: "1"` と `stop_id: "5"` の両方が含まれる場合、運行情報(alert)は停留所等(stop) 5 におけるルート・路線系統(route) 1 にのみ適用するべきです。ルート・路線系統(route) 1 上の他の停留所等(stop)には適用するべきではなく、停留所等(stop) 5 における他のルート・路線系統(route)にも適用するべきではありません。

複数のエンティティに影響する運行情報(alert)（例: ルート・路線系統(route) 1 と停留所等(stop) 5 の両方に対する運行情報(alert)）を表現したい場合は、`alert` に複数の `informed_entity` を追加するべきです。それぞれが影響を受けるエンティティに適用されます（例: ルート・路線系統(route) 1 を含む `informed_entity` を1つ、停留所等(stop) 5 を含む `informed_entity` をもう1つ）。

## 原因 {: #cause}


この運行情報(alert)の原因は何ですか？以下のいずれかを指定することができます。

*   不明な原因
*   その他の原因（これらの選択肢のいずれにも該当しないもの）
*   技術的な問題
*   ストライキ
*   デモ
*   事故
*   休日
*   天候
*   保守
*   建設
*   警察活動
*   医療上の緊急事態
*   特別イベント

## 影響 {: #effect}


この問題は、指定されたエンティティにどのような影響を与えますか？以下のいずれかを指定することができます。

*   運休
*   減便
*   大幅な遅延（軽微な遅延は[便の更新(trip update)](../trip-updates)を通じてのみ提供するべきです）。
*   迂回
*   増便
*   運行変更：運行が、乗客が通常期待する内容と異なります。例として、その曜日の通常運行とは異なる今後の祝日ダイヤについて乗客に注意を促す運行情報(alert)があります。
*   停留所等(stop)の移設
*   その他の影響（これらの選択肢のいずれにも該当しないもの）
*   不明な影響
*   影響なし：運行情報(alert)は乗客に情報を提供しますが、運行には影響しません。例には、公開会議の告知やアンケートによるフィードバックの募集が含まれます。
*   アクセシビリティの問題：運行情報(alert)は、段差のないアクセスに影響するアクセシビリティの問題に関する情報を提供します。例には、故障中のエレベーターや可動式スロープが含まれます。
