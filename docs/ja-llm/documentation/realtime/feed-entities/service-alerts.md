# 運行情報(alert) {: #service-alerts}


運行情報(alert)を使用すると、ネットワーク上で障害が発生した際に更新情報を提供できます。個別の便(trip)の遅延および運休は、通常、[便の更新(trip update)](../trip-updates)を使用して通知するべきです。

以下を提供することができます。

*   URL - 運行情報(alert)について詳しく説明するサイトへのリンク
*   Header text - 運行情報(alert)の要約
*   Description - 運行情報(alert)の完全な説明。これは常にヘッダーとともに表示されるため、この情報を繰り返すべきではありません。

## TimeRange {: #timerange}


運行情報(alert)は、指定された時間範囲内で適切な場所に表示されます。この範囲は、乗客が運行情報(alert)を確認することが有用である期間全体をカバーするべきです。

時刻が指定されていない場合、運行情報(alert)はフィード内に存在する限り表示されます。複数の範囲が指定されている場合、それらすべての期間中に表示されます。

## EntitySelector {: #entityselector}


エンティティセレクタを使用すると、この運行情報がネットワークのどの部分に影響するかを正確に指定できるため、ユーザーに最も適切な運行情報のみを表示できます。複数のエンティティに影響する運行情報には、複数のエンティティセレクタを含めることができます。

エンティティは GTFS 識別子を使用して選択され、以下のいずれかを選択できます。

*   事業者 - ネットワーク全体に影響します
*   ルート・路線系統(route) - ルート全体に影響します
*   ルートタイプ - このタイプのすべてのルートに影響します。例: すべての地下鉄。
*   便(trip) - 特定の便に影響します
*   停留所等(stop) - 特定の停留所等に影響します

1つの `informed_entity` に、上記のフィールドを複数含めることができます。1つの `informed_entity` に複数のフィールドが含まれる場合、それらは `AND` 論理演算子で結合されているものとして解釈するべきです。言い換えると、運行情報は `informed_entity` で指定されたすべてのフィールドを満たすコンテキストにおいてのみ適用するべきです。たとえば、`route_id: "1"` と `stop_id: "5"` の両方が1つの `informed_entity` に含まれる場合、運行情報は停留所等 5 におけるルート 1 にのみ適用するべきです。ルート 1 上の他の停留所等には適用してはいけません。また、停留所等 5 における他のルートにも適用してはいけません。

複数のエンティティに影響する運行情報（例: ルート 1 と停留所等 5 の両方に対する運行情報）を表現したい場合は、`alert` に複数の `informed_entity` を追加するべきです。それぞれが影響を受けるエンティティに適用されます（例: ルート 1 を含む1つの `informed_entity` と、停留所等 5 を含む別の `informed_entity`）。

## 原因 {: #cause}


この運行情報(alert)の原因は何ですか？以下のいずれかを指定することができます。

* **不明な原因**: 障害の原因が不明である、または特定されていない場合に使用します。より具体的な原因を合理的に特定できる場合は、使用を避けるべきです。
* **その他の原因**: 定義済みの選択肢のいずれにも該当しない原因に使用します。
* **技術的問題**: 車両またはインフラの故障に関連する問題です。例には、機械的故障や情報システムのバグが含まれます。
* **ストライキ**: 交通事業者または運行事業者が関与する労働ストライキによって生じるサービスの障害です。
* **デモ**: 公共のデモ、抗議活動、または集会によって生じるサービスの障害です。
* **事故**: サービスを妨げる衝突や脱線などの事象です。
* **祝日**: サービスの変更につながる可能性がある公休日です。
* **天候**: 雪、嵐、洪水などの気象条件によって生じる障害です。
* **保守**: サービスに関連する計画的な保守です。例には、線路保守、エレベーター保守、車両保守が含まれます。
* **工事**: サービスに関連するかどうかにかかわらず、サービスに影響を与えるあらゆる工事です。例には、駅の建設やバス路線に影響を与える道路工事が含まれます。
* **警察活動**: 法執行活動またはセキュリティ上の事象による障害です。例には、捜査やセキュリティ上の脅威が含まれます。
* **医療上の緊急事態**: 乗客または職員の医療上の緊急事態に関わる事象です。例には、列車の停止を余儀なくする車内での医療上の問題が含まれます。
* **特別イベント**: パレード、祭り、公演、ファーマーズマーケット、スポーツイベントなどの、特別な一回限りまたは定期的なイベントです。

## 影響 {: #effect}


この問題は、指定されたエンティティにどのような影響を与えますか？以下のいずれかを指定することができます。

* **運休**: 指定されたエンティティに対する公共交通サービスがありません。
  * 事業者の場合、当該事業者のすべてのルート・路線系統(route)が運行していません。
  * ルート・路線系統(route)の場合、当該ルート・路線系統(route)のすべての便(trip)が運行されません。
  * 便(trip)の場合、当該特定の便(trip)が運休となります。
  * 駅（`location_type` = 1）または停留所等(stop)（`location_type` = 0）の場合、乗客は乗車または降車できません。
* **減便**: 便(trip)の本数または頻度が減少します。
* **大幅な遅延**: ルート・路線系統(route)が継続的に遅れて運行します（軽微な遅延は[便の更新](trip-updates.md)を通じてのみ提供するべきです）。
* **迂回**: ルート・路線系統(route)のルート形状(shape)が変更され、一部の停留所等(stop)での乗車／降車に影響する可能性があります。
* **増便**: 便(trip)の本数または頻度が増加します。例えば、特別イベントに対応するために、より多くのバスが運行されます。
* **変更されたサービス**: 運行が、乗客が通常期待する内容と異なります。例として、その曜日の通常運行とは異なる今後の祝日ダイヤを乗客に知らせる運行情報(alert)があります。
* **停留所等(stop)の移設**: 停留所等(stop)の位置が一時的または恒久的に変更されます（恒久的な変更であることが判明している場合は、新しい位置がスケジュールデータに反映されていることを確認してください）。
* **その他の影響**: これらの選択肢のいずれにも該当しません。
* **不明な影響**: 影響がまだ特定されていない運行情報(alert)に使用します。運行情報(alert)の影響が判明している場合、または運行情報(alert)のヘッダーまたは説明から推測できる場合は、「不明な影響」を使用してはいけません。
* **影響なし**: 運行情報(alert)は乗客に情報を提供しますが、運行には影響しません。例には、公開会議の告知やアンケートによるフィードバックの募集が含まれます。必要な場合を除き、この影響を使用しないことが推奨されます。
* **アクセシビリティの問題**: 運行情報(alert)は、段差のないアクセスに影響するアクセシビリティの問題に関する情報を提供します。例には、故障中のエレベーターまたは可動式スロープ、ニーリングできないバス、またはホームと車両の間隔が大きい列車による例外的なサービスが含まれます。
