## 📂 アクティブな提案 {: #active-proposals}


**[shapes を含めるべきであることを追加 #470](https://github.com/google/transit/pull/470)**

この変更では、shapes.txt に「should」の記述を追加し、ゾーンベースのデマンド型サービスを GTFS でモデル化できるようになったため、すべての場合に推奨とするのではなく、すべてのルートベースのサービスに shapes.txt を含めるべきであることを指定します。

**[デマンド型サービスに伴う stops.txt の存在要件の変更 #472](https://github.com/google/transit/pull/472)**

この PR は、flex の採用後に stops.txt の存在要件を更新し、必須から条件付き必須（locations.geojson が存在しない場合は必須、それ以外の場合は任意）へ変更することを提案しています。

**[stop_times.txt の timepoint の意図された使用方法を明確化 #474](https://github.com/google/transit/pull/474)**

この変更では、stop_times.timepoint の空の値の意味を明確化し、空の値は stop_times.txt のいずれのレコードにも timepoint 値が提供されていないことを意味し、提供される場合は、時刻が関連付けられているすべてのレコードに 0 または 1 の timepoint 値を設定しなければならないことを指定します。

**[locations.geojson のポリゴンに対する妥当性ルールを追加 #476](https://github.com/google/transit/pull/476)**

この PR は、GTFS においてポリゴンが無効となり得るすべての方法を記述する代わりに、flex ポリゴンの妥当性ルールを改善するため、OpenGIS Simple Features Specification のセクション 6.1.11 を参照することを提案しています。

## 🔥 最も活発な議論 {: #most-active-conversations}


**[shapes の使用に関するベストプラクティス #477](https://github.com/google/transit/issues/477) **

Bliksem Labs B.V. の Stefan は、shape が具体的なものか抽象化されたものか、また無関係な停留所等(stop)の連続間で共有されているかを指定することを含め、shape の特性を判定するために使用できる新しいファイルを追加することを提案しています。すべての停留所等(stop)地点に shape point を作成する慣行も、ここで提案されています。

**[feed_info.txt における中心座標または Bounding box の定義 #471](https://github.com/google/transit/issues/471) **

Mathematician の Mustafa は、地図上でそのデータセットが表すエリアに焦点を合わせるための中心点を示すフィールドを feed_info.txt に追加することを提案しました。

**[提案: エレベーター／エスカレーターのリアルタイム状態を追加 - ノードのみではなく構内通路(pathway)を選択するよう EntitySelector を拡張 #268](https://github.com/google/transit/issues/268) **

wheelmap.org の Sebastian は、RT フィードが構内通路(pathway)を選択してその realtime 状態を伝達できるように EntitySelector を拡張し、GTFS が Realtime でエレベーターまたはエスカレーターの運休をフラグ付けできるようにすることを提案しました。この議論は最近、SimplifyTransit の Cody によって再び活発化しました。

**[グローバル trip id #462](https://github.com/google/transit/issues/462)**

SKI+ の David は、終日にわたり有効な便(trip)識別子の必要性に対応するため、NeTEx や HRDF などの他の標準とのより良い統合を目的として、GTFS Schedule および Realtime に新しいフィールド「trip_global_id」を追加することを提案しています。このグローバル ID により、異なるデータ形式間での旅行情報のマッピングが容易になります。 

**[GTFS static への vehicles.txt の追加 #458](https://github.com/google/transit/issues/458)**

TransSee の Darwin は、GTFS に `vehicles.txt` ファイルを追加することを提案しています。これにより、車両定員、アクセシビリティ、および機能に関する詳細情報を提供でき、リアルタイム予測ツールを強化し、車両群データの報告を標準化できます。このファイルには、車両タイプ、定員、製造者、およびアクセシビリティ機能などの詳細を含めることができます。
