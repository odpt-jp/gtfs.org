# [GTFS Digest] 2025年3月 - ガバナンス提案に対するコミュニティの意見と Validator リリース: Flex + Rider Categories {: #gtfs-digest-march-2025-community-weighs-in-on-governance-proposal-validator-release-flex-rider-categories}


2025年3月の GTFS Digest では、GTFS Schedule Governance Proposal に対するコミュニティレビューと、完全な Flex 検証ルールおよび GTFS-Fares v2 の Rider Categories をサポートするようになった GTFS Validator v7.0 のリリースを取り上げます。デマンド型交通(DRT)の更新と、TripUpdate.schedule_relationship = ADDED の非推奨化について、2件の投票が進行中です。進行中の提案には、cEMV 非接触決済のサポートおよびカーフェリーの許容が含まれます。

## 🗳️ 現在投票中 {: #currently-voting}


[**booking_rules.txt における continuous pickup/dropoff の値およびフィールド Type に関する明確化 #528**](https://github.com/google/transit/pull/528)  
この PR は、デマンド型サービス（DRT）に特化した明確化を導入し、start_pickup_drop_off_window/end_pickup_drop_off_window が指定されている場合に continuous_pickup/continuous_drop_off に値 1 を使用できるようにします。

[**TripUpdate.schedule_relationship = ADDED を非推奨とし、GTFS static のスケジュールに基づいて運行されない新規／置換便を指定するために TripUpdate.schedule_relationship = NEW / REPLACEMENT を追加します。#504**](https://github.com/google/transit/pull/504)  
更新された提案は、GTFS Realtime における TripUpdate.schedule_relationship = ADDED の非推奨化と、GTFS Schedule に存在しない便を示すための TripUpdate.schedule_relationship = NEW および TripUpdate.schedule_relationship = REPLACEMENT の使用に焦点を当てており、新しい値は experimental としてフラグ付けされています。

## 📂 進行中の提案 {: #active-proposals}


[**trips.txt に cars_allowed フィールドを追加 #547**](https://github.com/google/transit/pull/547)  
この PR は、trips.txt に cars_allowed フィールドを追加することを提案しています。フェリーの自動車情報を GTFS に追加する方法については、[issue #466](https://github.com/google/transit/issues/466) で多くの議論がありました。議論は、stop_times.txt を用いるアプローチと trips.txt を用いるアプローチのどちらを使用するかを中心に行われました。 

[**communication_period および impact_period を追加 #546**](https://github.com/google/transit/pull/546)  
この提案では、2つの新しいフィールドを導入します。communication_period は運行情報(alert)を表示するべき時間を指定し、impact_period はサービスが障害の影響を受ける時間を指定します。さらに、一貫性を保つため、これらの新しいフィールドが active_period と相互排他的であることを保証するルールを定めます。

[**agency.txt および routes.txt に cemv_support フィールドを追加 #545**](https://github.com/google/transit/pull/545)  
この提案では、agency.txt および routes.txt に新しい cemv_support フィールドを導入し、乗客が特定の事業者またはルート・路線系統(route)における交通サービスを利用するために cEMV（非接触型 Europay、Mastercard、および Visa）を使用できるかどうかを示します。 

[**[ガバナンス] 新しい GTFS Schedule ガバナンス提案 #544**](https://github.com/google/transit/pull/544)  
MobilityData は、2年間にわたるコミュニティからのフィードバックに基づき、現在の GTFS ガバナンスプロセスの更新を提案しています。主な改善には、より明確な文書化、構造化された提案フェーズ、および改訂された投票要件が含まれます。現在、これらの変更を採用するための投票を呼びかける前に、最終的な議論を募集しています。

* 議論およびレビュー期間は4月中旬まで継続するべきです。  

[**便の変更に関するさらなる明確化 #542**](https://github.com/google/transit/pull/542)  
この提案では、GTFS Realtime における便の変更(trip modification)について、ルート形状(shape)、ID の使用、およびエンティティのリンクに関するさらなる明確化を追加します。また、一貫性を保つため、TripProperties における shape_id の定義をリファレンスと proto の間で整合させます。

[**original_trip_id による GTFS Schedule および Realtime の強化 #534**](https://github.com/google/transit/pull/534)  
Davidr1234 は、Google Transit 拡張の `original_trip_id` を GTFS Schedule と GTFS Realtime の両方で採用することを提案しています。これにより、GTFS と、同様の概念を持つ SIRI や NeTEx などの他の標準との間で、便(trip)をシームレスに参照できるようになります。

## 🔥 最も活発な議論 {: #most-active-conversations}


[**旅行の途中で車両の連結／切り離しを可能にするため、着席したままの乗換の要件を緩和する #548**](https://github.com/google/transit/issues/548)  
Michael は、National Rail network で一般的な、旅行の途中で車両が連結／切り離しされる場合における、着席したままの乗換に関する現在の要件に疑問を呈しています。彼は、transfer_type = 4 の要件を緩和することを提案しています。 

[**ベストプラクティス: 一意な ID における妥当な長さ #518**](https://github.com/google/transit/issues/518)  
Stefan は、GTFS feed で使用されるあらゆる ID に推奨文字数上限を設定するベストプラクティスを導入し、値が 36 bytes を超えた場合に validator warning を発生させることを提案しています。

[**複数形のフィールド名？ #536**](https://github.com/google/transit/issues/536)  
Nina は、GTFS において「Many」の多重度(cardinality)を持つフィールドに、複数形ではなく単数形の名前が付けられている理由に疑問を呈しています。回答では、CSV の各行には単一の foreign key reference のみが含まれるため、列名はコレクションを表すのではなく、個々の行に適用されると説明されています。

## 🛠️ ツールの更新 {: #tools-update}


[新しい GTFS Schedule Validator リリース: Rider Categories とすべての Flex ルール**](https://github.com/MobilityData/gtfs-validator/releases/tag/v7.0.0)  
GTFS Schedule Validator 7.0 リリースには、以下が含まれます。

* 🧒 👵 👨 GTFS-Fares における乗客カテゴリのルール。Rider Categories は、成人、子ども、高齢者、学生など、年齢、属性、またはニーズに基づいて異なる運賃設定が適用される可能性がある乗客のグループです。   
* 📞🚌 Flex ルールの完全な一覧。[GTFS Flex](https://gtfs.org/community/extensions/flex/) は、乗客がデマンド型サービスを見つけ、それらの予約方法を確認できるようにする提案です。Flex は昨年、正式に GTFS に採用されました。この validator リリースでは、Flex の検証ルールの完全な一覧を提供します。 

[質問やフィードバックは、こちらのディスカッションスレッドで共有してください。](https://github.com/MobilityData/gtfs-validator/discussions/2011)
