# [GTFS Digest] 2024年3月 - GTFSがFlexを採用し、Trip-Modificationsを試験的に導入 {: #gtfs-digest-march-2024-gtfs-adopts-flex-and-experiments-with-trip-modifications}

GTFS-Flexにより、ユーザーはデマンド型サービスを発見できるようになりました。また、GTFS Trip-Modificationsでは、便の調整に関する試験的なフィールドが導入されています。Canonical GTFS Schedule Validatorの新しい5.0リリースには、強化されたエラー処理とFares v2の検証が含まれています。

GTFS Digestは、[MobilityData](https://mobilitydata.org/)が毎月作成する、GTFSに関する開発状況の概要を提供するリソースです。

## 🚀 最近採用された項目 {: #recently-adopted}


**[GTFS-Flex [Voting ver.] #433](https://github.com/google/transit/pull/433)**

GTFS-Flex 提案により、乗客は旅程検索ツール上でデマンド型サービスを見つけることができます

**[GTFS Trip-Modifications #403 ](https://github.com/google/transit/pull/403)** **[**experimental field として投票可決**]**

Trip-Modifications は、ルート形状(shape)を変更し、運行されない停留所等(stop)を削除し、必要に応じて一時的な停留所等(stop)を追加するために便(trip)に対して行われる変更です。Trip-Modifications は主に、迂回経路の可視化およびリアルタイム予測の更新に使用されます。

## 📂 有効な提案 {: #active-proposals}


**[GTFS real time FeedHeader に Feed Version と GTFS url を追加 #434](https://github.com/google/transit/pull/434)**

この Realtime 提案では、GTFS real time データとともに使用する GTFS schedule ファイルに関する情報を提供するため、feed header に2つの新しいフィールドを追加します。feed_version は GTFS の feed_info.txt ファイル内の feed_version と一致し、GTFS_url は GTFS ファイルの url を指します。この変更を実装する意思のある producer が、先に進めるために必要です。

**[route-based fare_rules における stops.zone_id の条件付き要件を明確化 #432](https://github.com/google/transit/pull/432)** \
この提案は、stops.zone_id の条件付き要件を変更し、停留所等(stop)が、fare_id と route_id のみが定義された fare_rules.txt レコード（route-based fares）に route_id が存在する trip_ids にのみ割り当てられているシナリオを許可します。

## 🔥 最も活発な議論 {: #most-active-conversations}


**[[Governance] フェーズ2: 投票とレビューの強化 #436](https://github.com/google/transit/issues/436)**

この GitHub Issue は、2023年12月に公開された[段階的計画](https://github.com/google/transit/issues/413)のフェーズ2で概説された仕様改定プロセスを中心に、GTFS Governance を強化する継続的な取り組みの一部です。



* 2024年3月13日にインタラクティブな議論が開催されました。参加者はフィードバックを共有し、大まかな合意が得られました。
* 変更に関する詳細について合意形成を継続するため、まもなくワーキンググループが結成されます。
    * このグループへの参加に関心がある場合は、[MobilityData](mailto:specification@mobilitydata.org)までご連絡ください。

**[pathways.stair_count の制約に関する明確化 #437](https://github.com/google/transit/issues/437)**

Michael Kearney は pathways.stair_count の定義に潜在的な問題があることを指摘し、空の値および 0 の値の意味に関するいくつかの疑問を提起したうえで、議論のために4つの可能な解決策を提案しています。ただし、潜在的な後方互換性の問題も指摘しています。この Issue にはコミュニティによるさらなる議論が必要です。

**[二峰性サービス（バス + 鉄道）のモデリング](https://groups.google.com/g/gtfs-changes/c/GI0INQqSk4s/m/lLRhryaWAAAJ)**

Gustavo Franco は、特定のルールに従って異なる駅にサービスを提供する「二峰性サービス」を GTFS でモデリングする可能な方法について、コミュニティに質問しています。コミュニティのメンバーはすでに、このようなユースケースの解決に役立つ可能性がある以前の提案を示しています。

**[translations.txt で使用される言語コードデータ標準に関する明確化 #435](https://github.com/google/transit/issues/435)**

Trillium の Juliet Eldred は、翻訳で使用されるコードデータ標準に関するドキュメントの不整合を提起し、信頼できる情報源がどこにあるのかを明確にするため、コミュニティの協力を求めています。 

**[相乗り路線の統合 #430](https://github.com/google/transit/issues/430)**

フランスの National Access Point (NAP) の Aurélien は、バス路線のように振る舞う相乗り路線、すなわち正確な停留所等(stop)と目的地を持つ一方で、この場合は運賃から金銭的インセンティブを受け取る、または乗客と費用を分担できる一般の自動車運転者によって運行される路線をモデリングする可能性のある提案について議論するため、GitHub Issue を作成しました。議論のために2つの異なる可能な解決策が提示されています。

## 🛠️ ツールの更新 {: #tools-update}


**[新しい 5.0 リリース: Canonical GTFS Schedule Validator](https://github.com/MobilityData/gtfs-validator/releases/tag/v5.0.0)**

主な内容は以下のとおりです。



* エラー trip_distance_exceeds_shape_distance および equal_shape_distance_diff_coordinates のノイズを低減するためのしきい値の実装
* networks.txt および route_networks.txt 向けの新しい Fares v2 検証ルール
* 機械可読性を向上させるための JSON レポートに対する破壊的変更
