# [GTFS Digest] 2025年7月 - ガバナンス、新たな貢献者、新たな議論を祝して！ {: #gtfs-digest-july-2025-celebrating-governance-new-contributors-and-new-conversations}


GTFS Digestの新たな号へようこそ。今月は、コミュニティ主導のフィードバックを2年間にわたり受け、新しいガバナンスフレームワークが採用されました。変更内容にご興味がある場合は、[ドキュメント](https://github.com/google/transit/blob/master/gtfs/Governance/introduction.md)をご確認ください。現在、投票が行われている提案はありませんが、だからといってGithubが活発でないわけではありません！現在、かなり多くの議論が行われているため、詳細については続きをお読みください。

<!-- more -->

GTFS Digestは、GTFSに関する進展の概要を提供するために[MobilityData](https://mobilitydata.org/)が毎月配信しているリソースです。

皆様からのフィードバックを大切にしており、新しいレイアウトについてどう思われるかを知りたいと考えています。[このフォーム](https://forms.gle/GGefktvemnJD5Q9g8)にご記入いただき、このツールの可能性を最大限に引き出すためにご協力ください。

## 🐙 Github で最も活発な議論 {: #most-active-conversations-on-github}


*Github Issues は、新機能のアイデアや仕様に関する質問など、議論を始めるのに最適な場所です。以下は今月最も活発な議論です。*

| 議論 | 投稿者 | 説明 |
| :---- | :---- | :---- |
| [GTFS-realtime alerts の informed_entity に activities フィールドを追加 #573](https://github.com/google/transit/issues/573)  | natekauf | この issue は、GTFS Realtime Alert 仕様の informed_entity 内に新しい activities フィールドを追加することを提案しています。このフィールドには BOARD、EXIT、RIDE の列挙値が含まれ、特定の停留所等(stop)で利用できない乗客の行動を説明します。   |
| [routes レベルで必須の交通手段タイプは柔軟性に欠ける可能性がある（複数モードのルート・路線系統(route)） #409](https://github.com/google/transit/issues/409) | barbagus | この issue は、複数モードのルート・路線系統(route)における route_type の柔軟性不足の可能性について懸念を共有し、それに対処する可能性のある方法を提案しています。 |
| [block_id を必須の arrival_time および departure_time と併用すると、矛盾する情報が容易に発生する #569](https://github.com/google/transit/issues/569)  | bradyhunsaker | この issue は、GTFS feeds において block_id で関連付けられた便(trip)間の時刻不一致により、重複または競合する出発時刻が発生する、旅程計画アプリでの運行情報表示の問題を説明しています。彼は2つの修正案を提案しています。関連付けられた便(trip)間で時刻を一致させるか、終点の停留所等(stop)において意味を持たない時刻を省略できるようにすることです。 |
| [便(trip)レベルでのルートタイプの定義 #358](https://github.com/google/transit/issues/358) | vpaturet | この議論では、特定のルート・路線系統(route)内の便(trip)が代替の交通モードでスケジュールされる場合に備え、新しい「trip_route_type」フィールドを採用する可能性を検討しています。この issue には、PR #572 が開かれた後にいくつかの新しいコメントが寄せられています。 |
