# [GTFS Digest] 2025年8月 - セマンティクス明確化に関する投票など！ {: #gtfs-digest-august-2025-vote-on-a-semantics-clarification-and-more}


GTFS Digestの新しい号へようこそ。夏は終わりに近づいているかもしれませんが、GTFSに関する議論はそうではありません！GTFS Communityでは、新しいガバナンスプロセスの導入、新たな議論、新規貢献者の参加により、活発な夏となりました。その一環として、GTFS Communityの維持、成長、強化を担うMobilityDataの新しいGlobal Community Leadとして、Etienne Pichot Damonが加わりました。

<!-- more -->

GTFS Digestは、GTFSに関する進展の概要を提供するために、[MobilityData](https://mobilitydata.org/)が毎月配信するリソースです。

皆様からのフィードバックを大切にしており、新しいレイアウトについてどう思われるかを知りたいと考えています。[このフォーム](https://forms.gle/GGefktvemnJD5Q9g8)にご記入いただき、このツールの可能性を最大限に引き出すためにご協力ください。

## 🐙 Github で最も活発な会話 {: #most-active-conversations-on-github}


*Github Issues は、新機能のアイデアや仕様に関する質問など、会話を始めるのに最適な場所です。以下は今月最も活発な会話です。*

| 会話 | 作成者 | 説明 |
| :---- | :---- | :---- |
| [Add new SPECIAL_EVENT Cause to GTFS-realtime Service Alerts #576](https://github.com/google/transit/issues/576) | ckraatz | この issue は、GTFS-realtime Service Alerts に新しい「SPECIAL_EVENT」の原因を追加することを提案しています。 |
| [Reconsider fare_leg_rules.rule_priority matching semantics/spec wording #575](https://github.com/google/transit/issues/575) | jsteelz | この issue では、rule_priority の空のセマンティクスと、それが運賃区間ルールの照合に与える影響に関する複数の問題について議論しています。 |
| [RFC: mandatory shape_pt at at most 2m from stop #574](https://github.com/google/transit/issues/574) | skinkie | この issue は、各停留所等(stop)ポイントの近傍に少なくとも1つの偽ノードを追加することを提案する、ルート形状(shape)のベストプラクティスを提案しています。 |
| [Add activities field to informed_entity in GTFS-realtime alerts #573](https://github.com/google/transit/issues/573) | natekauf | この issue は、GTFS Realtime Alert 仕様の informed_entity 内に新しい activities フィールドを追加することを提案しています。このフィールドには、特定の停留所等(stop)で利用できない乗客の活動を説明する BOARD、EXIT、RIDE の列挙値が含まれます。 |
| [Add field for distance units #568](https://github.com/google/transit/issues/568) | nkemphues | この issue は、GTFS フィードに定義された距離単位がないことによって生じる問題を取り上げています。この提案では、shapes.txt や fare_legs.txt などのファイルで使用される単位を明確にするため、任意の distance_unit フィールドを追加することを提案しています。 |
